# 포트폴리오·면접용 정리

## 한 줄 소개

> 국내·미국 주식의 다양한 입력을 해석하고, 분포 기반 참고 신호를 웹 대시보드와 Telegram Bot으로 전달한 금융 데이터 풀스택 서비스

## 강조할 문제 해결 경험

### 1. 백테스트의 시점 오류 수정

종가로 계산한 신호가 같은 날 시가부터의 수익률에 반영되면 미래 정보를 먼저 사용하게 됩니다. 신호를 한 거래 구간 뒤로 이동해 적용하고, 이를 단위 테스트로 고정했습니다.

### 2. 사용자 입력과 데이터 공급자 티커의 간극 해결

한글 이름·별칭·KRX 코드·미국 티커를 하나의 해석 계층으로 묶었습니다. KOSDAQ 숫자 코드의 `.KQ` 접미사와 명시적 `.KS`/`.KQ` 입력의 메타데이터도 테스트로 보호합니다.

### 3. 외부 데이터 의존성을 서비스 수준으로 다룸

KRX 동기 조회는 이벤트 루프 밖에서 수행하고, KRX/Yahoo 검색에는 타임아웃과 재시도를 적용했습니다. 공급자 실패는 502로 구분해 사용자가 데이터 부재와 시스템 오류를 구별할 수 있습니다.

### 4. 분석 결과를 실제 사용 채널로 확장

차트 중심 웹 대시보드와 빠른 조회를 위한 Telegram Bot을 분리했습니다. Bot 별칭은 채팅 단위 SQLite로 관리해 그룹별 사용성을 고려했습니다.

## 이력서 문장 예시

- React·FastAPI 기반 주식 분석 서비스를 개발해 한글 종목명, 별칭, 국내외 티커를 통합 해석하고 가격·분포 기반 신호를 웹과 Telegram으로 제공
- 종가 기반 신호를 다음 거래 구간에 적용하도록 백테스트를 재설계해 미래정보 편향 가능성을 제거하고 전략 계산을 공통 모듈로 통합
- 외부 금융 데이터의 타임아웃·재시도·오류 응답을 구현하고 pytest와 GitHub Actions로 API·종목 해석·전략 규칙을 자동 검증

## 예상 질문과 답변 방향

| 질문 | 답변 핵심 |
| --- | --- |
| 왜 이 프로젝트를 만들었나요? | 금융 데이터의 복잡한 티커 입력과 조회 채널 문제를 실제 서비스 흐름으로 해결하고 싶었다고 설명 |
| 수익률이 좋은 전략인가요? | 연구용 참고 모델이며 비용·슬리피지·표본 외 검증이 없어 성과를 투자 전략으로 주장하지 않는다고 명확히 설명 |
| 왜 FastAPI인가요? | Pydantic 스키마와 비동기 라우팅으로 외부 데이터 API를 빠르게 구성하기 적합했다고 설명 |
| 외부 API가 느리거나 실패하면요? | 직접 티커의 빠른 경로, KRX off-loop 처리, 짧은 타임아웃·재시도, 502 오류 구분을 설명 |
| 가장 어려운 버그는 무엇이었나요? | 종가 신호와 시가 수익률의 정렬 오류, KOSDAQ 코드 접미사·메타데이터 보존 문제를 사례로 제시 |

## 보여줄 때의 주의점

- 전략의 수익률이 아니라 문제 정의, 신뢰성 개선, 사용자 전달 채널을 중심으로 설명합니다.
- 실제 화면 또는 Telegram 응답 캡처를 README에 추가하면 짧은 시간에 서비스 범위를 전달하기 좋습니다.
- “완벽한 투자 모델”보다 데이터의 한계와 검증 범위를 솔직히 설명하는 것이 면접에서 더 신뢰를 줍니다.
